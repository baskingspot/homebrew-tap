# AGENTS.md

Working notes for AI coding agents in baskingspot/homebrew-tap.

## What this is

The org's Homebrew tap. `Casks/` is generated by `tools/update.py` from the latest release of every org repo that has `.github/release.yaml`. The hourly `update.yml` workflow writes the casks, tests them on Homebrew, and commits them. Nobody edits `Casks/` by hand.

## Environment

The flake is the tool contract, from `baskingspot/nix`. `nix develop` provides Python, ruff, ty, and `yq`. The justfile is the command interface: `just test`, `just lint`, `just ci`.

## Rules

- Casks, not formulae. Our releases are prebuilt tarballs. Homebrew's policy is that prebuilt binaries are casks.
- The cask token is the repo name. The binary name comes from `release.yaml`. Don't give two repos the same token.
- The release binaries are not signed, so every cask clears `com.apple.quarantine` in `postflight`. Keep that.
- `update.py` fails loudly. A target it doesn't know is an error, a missing checksum is an error, and only a 404 means "this repo has no release.yaml". Any other API failure stops the run, so a flaky API never deletes a cask.
- A cask is removed only when its repo no longer has `release.yaml`, never because a release is missing.
- `update.yml` has the only write access, and it commits through the GraphQL API so the commit is signed. `check` must pass first.
- Change a cask's shape in `render()` and its test together. A cask is never tested by hand: the workflow installs it on Homebrew.
- Commit messages are one line, `area: summary`, and every commit is signed.
